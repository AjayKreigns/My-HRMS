3. **Idle prefetch.** Four seconds after the first page is up, the other pages' code is fetched one piece at a time while the browser is idle (admin tools only for admins). First visit to a page, after 9 s idle, on the phone profile:

| Page | Without prefetch | With prefetch |

| Finances | 272 ms | 78 ms |

| Admin pages | 126 ms | 133 ms |

Tried and reverted: **preloading the four common fonts** made first paint about 200 ms slower on all three pages (the extra 48 KB competes with the main script on a slow connection), so it was removed.

Not fixed:
- **Payroll opened directly** (a refresh on that page): largest paint 3.5 s before, 3.7 s now. The page needs the main script, then the admin code (64 KB compressed plus six shared page bundles), then renders a heavy page; the Archivo fonts add 173 KB after that. Reaching 2.5 s would need smaller admin code or fonts.

Ratings (Google's guidance): first paint good at 1.8 s or less (met on all pages); largest paint good at 2.5 s or less (met on Login and Home, not Payroll); blocked time good at 0.2 s or less and poor above 0.6 s (Home 0.55 s needs improvement, Payroll 0.73 s poor).

## Later the same day: audit, phone speed round 2

**Dependency audit: 0 issues** (was 2, both in development tools). Vite 5 moved to Vite 7 (7.3.8); `@vitejs/plugin-react` 4.7 works with it, build passes, all tests pass. Vite 8 was not needed.

**Phone speed** (375 px, 4x CPU slowdown, 1.6 Mbps, 150 ms latency, cache off, median of 3; old and new builds measured back to back, the machine is shared so readings move by about 0.1 s):

| Page | Before today | Now |
|---|---|---|
| Login | blocked 0.33 to 0.48 s, 263 KB | blocked 0.09 to 0.16 s, 261 KB |
| Home | content on screen 2.0 to 2.3 s, blocked 0.52 to 0.83 s | content 1.8 to 1.9 s, blocked 0.20 to 0.28 s |
| Payroll opened directly | content on screen 2.7 to 2.95 s, blocked 0.67 to 0.98 s, 449 KB | content 2.1 to 2.2 s, blocked 0.44 to 0.60 s, 277 KB |

What was changed, and what each gave:
1. **Fresh sample data no longer works out every locked month's payslips at page start** (`store.js`). It ran on every load, even on the sign-in screen, until the first edit saved the data. Now it runs just before the first edit. Biggest single gain: Login blocked time about 0.35 s to 0.1 s.
2. **The app is drawn as a React transition** (`main.jsx`), so the work is cut into small slices. Home blocked time about 0.3 s to 0.2 s.
3. **Payroll split into separate files** that load only when their tab opens (`Payroll.jsx` now holds Analytics; `PayrollRun`, `PayrollOps`, `PayrollSettings` and `payrollShared` are new). The Payroll chunk went from 38 KB to 9 KB compressed, and it no longer pulls in the leave, attendance and helpdesk admin screens (`adminShared.jsx`).
4. **Fonts:** only the Latin letters are shipped, plus the rupee sign cut out into a 700-byte file built into the stylesheet (was 33 KB of Jakarta "latin-ext" on almost every page, and 86 KB of Archivo on Payroll). Payroll download 449 KB to 277 KB.
5. **PF ceiling calculation** sorted its rules once per day of the cycle (`statutory.js`); now once. **Number formatting** uses one shared formatter instead of building one per amount (`utils.js`).
6. **Archivo uses `font-display: optional` on Payroll.** Without it the font arriving at about 2.1 s re-laid-out the page (about 0.25 s of blocked time) and pushed Chrome's largest-paint reading to 2.9 s. The cost: someone opening Payroll straight from its address on a slow connection with nothing cached sees the fallback font for that one page view; every later visit has Archivo.

Tried and removed: preloading the Payroll page's files from `index.html` (first paint 0.2 s later, blocked time higher), preloading the Archivo font (blocked time +0.15 s), batching layout reads (no change).

**Still open:** blocked time on Payroll opened directly is 0.44 to 0.60 s against the 0.3 s target. What remains is the first layout of the page shell (about 0.1 s of a 4x slowed phone) and drawing the Payroll analytics (about 0.2 s) plus its layout. Home meets the target on most runs; Login meets it.

**Measuring changes:** `perf.cjs` now also reports "content shown" (when the page's own content is drawn). Chrome's largest-paint reading sometimes never counts the text of a page that loads late, so on Payroll it can read as the first paint. First paint now reads about 0.6 s because the logo splash in `index.html` (added by the logo work) is drawn first, so use "content shown" for page-to-page comparisons.

**Build note:** Vite 7 fails on Windows when the terminal's folder starts with a lowercase drive letter (`c:\`) and `index.html` has an inline `<style>`; `vite.config.js` now sets the folder with a capital letter.
